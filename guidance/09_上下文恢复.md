# 技能 09 · 上下文恢复、可恢复事务和检查点

本技能的所有写入步骤为强制协议；普通教学只读时不创建无意义事务。若平台有真正事务则使用其机制并记录最终结果。若没有，按下面清单模拟可恢复提交，不声称原子性。核心指令及用户授权优先。初始化、升级涉及核心指令文件时也要记录操作范围、旧版备份与核验结果。

## 19.1 存储能力与恢复入口

将对话上下文视为可随时被压缩、截断或清空的临时工作区。不得假设模型能够获知压缩发生的时刻，也不得把上下文摘要视为完整历史。
启动时检查是否有真实、跨会话可访问的持久化存储和读写权限。沙箱临时文件、聊天文字和当前会话附件不自动等同于跨会话持久化。只能使用平台允许访问的指定目录，不擅自写入其他位置。
在系统提示词或固定项目配置中保留最小启动规则：知识库根目录、核心指令路径、总索引路径、人设档案路径、运行状态路径、恢复流程。没有自动加载 AGENTS.md 的能力时，必须显式读取。核心指令文件是辅助恢复依据，不得覆盖平台更高优先级规则。
如果根目录未知，询问一个关键问题（知识库保存在哪里），同时可继续单题讲解。若旧库暂不可访问，不得在其他目录创建一个同名空库或推断历史状态。

## 19.2 运行状态文件模板

在 07_Agent运行状态.md 中记录以下字段。未知信息填“未知”或“待补充”，禁止使用示例值冒充真实状态。
- 数据库格式版本、提示词版本、当前已提交数据修订号：
- 实际知识库根目录、总索引位置、核心指令位置、人设档案路径及修订号：
- 最后一次经核验的提交时间及事务 ID：
- 考试年份、备考阶段、当前学习章节：
- 各类下一个可用编号（以索引及预留事务核验）：
- 当前任务 ID、关联错题 ID、当前处理阶段：
- 已完成步骤、已提交内容、未提交内容及其事务路径：
- 待作答变式题或自测题 ID、完整题目、记录路径：
- 待批改的用户作答及关联事件 ID：
- 待复习任务 ID、到期日期及索引入口：
- 待验证的错因和待更新的掌握度：
- 恢复所需的下一步操作：
运行状态只存恢复所需的最小信息；完整历史、数学推导、答案与草稿保存在对应实体文件，不重复堆积在运行状态中。自测题答案可保存于内部记录，但在用户提交作答前不得展示。

## 19.3 每次任务的恢复和检索

1. 确认实际根目录及访问权限，读取核心指令（若未由平台加载）、总索引、人设档案、运行状态。
2. 检查待提交事务目录和最近更新日志，判断是否存在未完成提交、写入冲突或版本不一致。
3. 如果任务已提交，返回已有结果或继续后续步骤，不重复计数；如果有未完成事务，按本技能 19.5 恢复。
4. 根据当前题目或指令检索相关章节分片索引、知识点、解题方法、已确认短板和必要的历史错题。按稳定 ID 打开原记录核验，不仅凭摘要作判断。
5. 核对当前编号、关联 ID、复习状态及最近作答；从实际检查点继续工作。
每次新会话、恢复中断任务、模型切换或发现上下文不全时执行上述流程。普通连续任务也必须读取最新状态，不得仅依赖之前缓存。只讲题且不涉及历史诊断时可跳过持久化读取。

## 19.4 写入事务与检查点

每个独立作答使用稳定 A-ID。错因修正、批改、自测生成或复习任务变更记录对应事件或实体 ID，并关联已有的 A-ID（如适用）。按技能 03 的来源键和原始 ID 查找已提交索引及开放事务。同一次提交重试复用原事件及事务 ID，同一次作答后来补证据或订正时沿用 A-ID 并使用新事务。一次事务可变更多个实体。

支持原生事务时使用数据库事务。普通 Markdown 文件按下列顺序提交。

1. 读取最新已提交修订号及相关记录，核对事件、编号和关联。使用平台支持的锁或版本比较机制，无对应能力时采用单写入者模式。发现版本冲突即停止覆盖。
2. 在 `10_待提交事务/` 写入并回读事务清单。保存事务 ID、关联事件与实体 ID、适用的来源键、基准修订号 `base_revision`、目标修订号 `target_revision` 和“待提交”状态。清单逐项列出目标路径、可读取的写入前内容或备份（新文件注明原路径不存在）、完整预期内容或可重现的补丁及处理进度。目标包括实体、分片索引、衍生文件、提交候选日志、总索引与运行状态。能计算时保存写入前后的校验和，否则比较实际内容。
3. 按清单写入实体、分片索引及衍生数据，逐项记录进度。改写各目标前核对其写入前状态，遇到清单无法解释的改动按 19.5 处理。支持临时文件及原子替换时优先使用。恢复时，已经符合预期内容的项目直接标为已完成。
4. 回读核验内容、ID、事件去重、题目关联及可重算的统计。用同样的改写前检查写候选日志，将总索引和运行状态更新到目标修订号。回读所有目标文件并核验同一事务的候选日志和目标修订号。
5. 全部通过后将清单标为“已提交”，最后回读该标记。该标记是 Markdown 事务的提交点，候选日志及目标修订号用于核验。报告成功时提供事务 ID、已提交修订号、更新摘要及下一步。保留必要的事务历史与未提交清单。
需要即时保存的事件包括：完成错题分析、接收重要原始作答、确认或修改错因、生成待作答题、完成批改、调整掌握度、改变复习任务、更新学习配置或已确认的长期偏好。长任务按自然阶段建立检查点。平台若提供压缩前通知，立即尝试保存尚未提交的数据；无通知时依靠日常检查点。

## 19.5 中断、部分写入与失败恢复

发现开放事务时，读取清单和当前文件，逐项比较写入前状态与预期写入后内容。恢复分类如下。

| 核验结果 | 恢复动作 |
|---|---|
| 所有目标符合预期，其中总索引和运行状态已到目标修订号，候选日志也匹配本事务 | 补写并回读“已提交”标记，使用原事务 ID 和目标修订号 |
| 每个目标均匹配写入前或预期写入后状态，但还有步骤未完成，索引及日志的差异可由本事务解释 | 仅补写未完成项，按原顺序回读并提交 |
| 存在清单无法解释的内容、版本或其他事务改动 | 保留双方数据并停止覆盖。能安全核验合并时完成核验，否则标记待修复并说明冲突 |

总索引已经推进到本事务的目标修订号时，先结合内容和候选日志按上表判断。旧版清单如缺少目标修订号，仅在现有日志、修订号及目标内容能共同验证该事务的情况下补齐清单，否则保留待修复。仅在原版本可靠、且能保护其余合法改动时执行回滚。

查询时如暂无法完成恢复，只能使用清单备份等可核验的上一次已提交内容。无法还原相关范围时报告该部分暂不可核验。重启或重试复用原事务 ID，已存在的 Q-ID、A-ID 和复习任务照常引用。若连事务清单都无法保存，输出未保存增量、关联 ID 或临时 ID、原题及证据、目标路径、已执行步骤、失败原因和恢复入口。

## 19.6 按需加载与 Token 控制

常规任务默认只读取总索引、人设档案、运行状态、未提交事务、短板摘要、当前章节索引及少量相关实体。先检索 ID，再读取详细内容；不要为分析一道题加载所有错题。
索引按学科、章节分片，更新日志按月分片；原始错题、知识点、方法、公式和复习任务分别使用独立实体文件。不要将全部历史记录反复写入单个超长 Markdown 文件。搜索索引可以重建，但原始题目、作答事件和证据不能仅靠摘要重建。
执行全库统计、迁移、导出或完整性检查时，按批次读取和处理，记录批次进度、已处理 ID 和最后检查点。长期统计保留统计范围、样本量、更新时间和依据；摘要过期时按需重算。

## 19.7 数据格式与索引规范

每个 Markdown 实体可使用 YAML front matter 或等价结构化字段。至少记录：id、kind、chapter、created_at、updated_at、revision、status、关联 ID。数学题原文、作答过程及详细解析保留在正文中。
原始作答事件保存 A-ID、题目 Q-ID、发生时间、作答文本或附件引用、提示使用情况、实际结果及证据来源。有稳定来源时保存 03 定义的 `source_key`，供重启去重。更正原始记录时保留修订说明。诊断、掌握度和短板画像可按实际证据更新。
题目指纹用于查找同题候选，再核验数学内容。事件去重使用来源或已有 ID，同题实际重做使用新的 A-ID。附件实际可持久化访问时使用相对路径或有效引用，否则保留已核验的题目转写并注明附件不可用。
更新日志记录事务 ID、事件 ID、基准及目标修订号、涉及条目、变更摘要、核验结果和恢复说明。候选日志记录写入核验时间，读取已完成提交时将日志与最终清单标记核对。

## 19.8 完整性检查与事实来源

检查编号是否唯一、关联目标是否存在、索引是否能定位真实记录、事务与提交版本是否一致、复习是否重复、掌握度是否有证据，以及统计能否从原始作答事件重建。
事实来源优先顺序：用户当前明确提供的修正与证据 > 持久化原题及原始作答记录 > 已核验的知识库条目 > 提交日志 > 可访问的聊天原文 > 上下文压缩摘要 > 模型推测。
存在冲突时明确记录证据差异，不擅自用摘要或推测覆盖原始数据。未知信息不能作为已确认高频错因；无法读取全部历史时，统计注明可访问范围，不宣称全库结论。

## 19.11 无持久化权限时的降级规则

可以继续分析题目、提供练习并根据当前可访问证据提出建议，但不得声称完整历史已保存或下一会话一定能恢复。输出“未持久化保存”及本次完整增量、待作答题目和恢复检查点。需要用户手动保存时给出可复制的 Markdown 数据。
如果具备文件生成能力但生成文件只在当前会话可用，应说明其生命周期限制；用户可以保存到自己的知识库，随后在新会话重新导入。导入时先核对事件 ID 和版本，避免重复。

## 19.12 最终原则

上下文可以压缩，已核验且实际持久化的学习记录应能独立于聊天历史恢复。任何恢复保证都依赖真实的存储、访问权限、完整数据、固定入口和正确执行。不得将提示词本身当成数据库、自动定时器或永久记忆。

## V4.0 加强项
- 增加人设、教学经验、学习进度、知识图谱、作答事件及技能版本/路径的恢复入口；旧文件缺失先确认不是权限/网络故障。运行状态只保留待答 Q-ID 与记录路径，必要时附完整题面；不在公开恢复摘要泄露答案。记录任务阶段、批处理游标、待修复事项和实际已提交数据修订号。
- 提交与恢复以 19.4、19.5 的清单、核验顺序和恢复判定为准，重试沿用原事件及事务。已生成但未保存的用户原始信息应及时输出增量供手动备份。
- 当前会话可缓存已核验文件及 revision，下一库任务先比较最新实际 revision、待提交事务和相关实体；不可靠则重读。短板摘要、人设动态快照等衍生文件可延迟重建但标“过期/依据版本”，原始证据和待答任务必须及时保存。批量按题/小批次检查点，报告真实完成范围与未完成项。
- 无跨会话权限时区分“当前会话文件生成成功”“真实持久化已验证”；可读但不可写时只读分析并输出待提交增量。不要以文本模拟工具执行。若不能生成完整持久化数据，至少给原题、作答、关联或临时 ID、变更、未保存内容、失败原因及恢复步骤。若待答题答案应隐藏，将公开题面与核验答案分开存储/处理。
- “保存检查点”“恢复上下文”“查看运行状态”：按上述规则；查询状态只报告实际读取和核验结果。
